What this branch adds

Compared with its parent, cursor/notebook-playwright-tests-91a1, this branch does not change the notebook, the Rust CLI, or the Python CLI. It adds one folder: a local web app for .dql files.

The app, in one screen start here

You run it on your machine. A browser tab shows the folder you started in. The top bar switches two views. The left side is the files.

Query

Open a .dql file. The editor colors the language. Each query gets a light band. Writes are red, and neighboring writes use two reds so they stay separate.

A thin black border marks what Run selection will execute. A highlight runs that highlight. A cursor with no highlight runs the query it is sitting in. Ctrl+Enter does the same thing while the editor is focused (⌘Enter on a Mac). The shortcut is written under the button.

Tables

The same list as ls, with the same globs (nb_*, *foo*). Open a table and it shows 50 rows at a time, with Previous and Next.

Files

The tree is nested folders plus .dql files. Right-click to create, duplicate, rename, move, or delete. Drag onto a folder to move. Double-click a name to rename it. Typing in the editor writes the whole file back to disk.

The new folder dqlrs-web/

About 2,700 lines are this app. About 24,000 lines are a copy of the CodeMirror editor, vendored so the page does not need a network or a build step. Four pictures are the earlier mockups.

README.md 13 lines

How to start the app, and a short description of the editor, the highlight rules, the run shortcut, and the file tree.

run.sh 24 lines

Starts the server. By default it talks to DynamoDB Local on localhost:8000 with dummy AWS keys, and looks for a dqlrs binary you already built. --aws talks to AWS instead. --dir is the folder the tree shows.

Python 4 files

The server is the standard library only. No new packages.

server.py 227 lines

Listens on 127.0.0.1:8765. It serves the page, and a JSON API for the tree, reading and saving a file, creating a file or folder, duplicate, move, delete, running a script, listing tables, and paging rows.

engine.py 239 lines

Holds one dqlrs --serve process open. That command returns only the last statement, so a script is split and each statement is run on its own. The table list is ls. A page of rows is a SCAN with a rising LIMIT, then the last 50 rows.

files.py 228 lines

Every path stays inside the folder you started in. The tree shows directories and .dql files. Empty folders stay visible. Folders that only contain other kinds of files stay hidden. This file creates, saves, moves, duplicates, and deletes. A folder delete stops if it would remove something that is not a .dql file. A duplicate is named name copy, then name copy 2.

statements.py 55 lines

Splits a script on semicolons. Quotes and -- comments are left intact. A comment-only fragment is dropped.

Editor and highlight toggles

CodeMirror is set up here, with DQL colors. Two checkboxes: Minimal write highlight (a red bar in the gutter instead of a red background) and Even/odd highlight (the alternating bands). Both are saved in the browser under dqlrs-web.highlight. Even/odd starts on. Minimal starts off.

What Run executes

The border and the button use the same range. A non-empty selection is that selection. Otherwise it is the query around the cursor, including a comment that touches it and the blank line that closes it. The border is black, 1px, at 50% opacity.

Saving

There is no save button. After you stop typing for 400ms, the whole editor text is sent back and replaces the open file. Opening another file, running, moving, or duplicating also saves first. Loading a file into the editor does not count as an edit.

The file tree

A click opens a file or expands a folder, after a short pause so a double-click can rename instead. The right-click menu is New file, New folder, Duplicate, Rename, Move to…, and Delete. Dragging onto a folder moves the entry there. Dropping on the empty part of the tree moves it to the workspace root. If you rename or move the file that is open, the editor follows it.

dql-tokens.js 280 lines

The word lists: statements, schema words, types, functions, and the command words such as LS and HELP. DROP and DELETE are the red words. Adding a word here extends the highlighter.

It also finds each query. A blank line ends one and keeps the previous color. A comment with no blank line between it and a query uses that query’s color. A comment sandwiched between two queries stays with the earlier one. runTarget is the range Run will execute.

dql-mode.js 149 lines

Connects those rules to CodeMirror. Line backgrounds for the bands. Gutter bars when minimal write highlight is on. The black border around the run range.

The order it was built

Oldest first. This is the shape of the work, not a release list.

  1. Picture mockups of a query screen and a tables screen.
  2. A second, denser pair of mockups, with a nested tree and ls-style search.
  3. The real app: tree, editor, run, results, tables, 50-row pages.
  4. DQL syntax colors, using CodeMirror.
  5. A light band on alternate queries, and red on writes. DROP and DELETE are red words.
  6. Even writes use a darker red than odd writes.
  7. A blank line ends a band and keeps the previous color. A touching comment joins the query.
  8. The sample posts.dql grows to show those cases.
  9. Toggles for a gutter-only write mark, and for turning even/odd bands off. Both are remembered in the browser.
  10. A border around the query or selection that Run will execute, and Ctrl+Enter in the editor.
  11. That border becomes 1px, black, at half opacity.
  12. Right-click, drag, and double-click for files and folders.
